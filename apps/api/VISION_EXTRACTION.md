# Vision Extraction — photo of a leaflet / screenshot → event

A parent photographs a school leaflet, a noticeboard poster, or a WhatsApp
screenshot on `/events/new` and gets the same schema-valid `ParentEvent` draft
the text path produces. Shipped 2026-06-11 (NEXT_MOVES move 2); decision record
in [`ADL.md` ADR-018](../../ADL.md).

## Pipeline

```
phone camera / file picker
  └─ client: canvas downscale → ≤1568px JPEG q0.8 (EXIF-aware, ~200–500 KB)
       └─ POST /api/extract  { image_data_url: "data:image/jpeg;base64,...", raw_text: caption? }
            └─ extract_event(): instructor + gpt-4o (TOOLS), prompt v3v,
               response_model = ParentEventDraft → draft_to_event() → ParentEvent
```

The image travels **inline as a base64 data URL and is never persisted** — no
S3, no CDN, never logged (the `extraction_prompt` DEBUG log records the system
prompt and user text only, never the base64 image). Same `instructor` contract,
quota metering, and draft-review UI as text extraction.

## Decisions (rationale in ADR-018)

| # | Decision | Short why |
|---|----------|-----------|
| 1 | Vision-native structured output, **not** OCR-then-parse | Layout carries meaning (dates in headers, prices in small print); one call, one error mode; reuses the whole schema/eval machinery |
| 2 | Inline base64, **no S3 / no retention** | Photos of children's school comms: not storing them deletes the retention problem; client downscale keeps the body ≲500 KB, far under Lambda's 6 MB |
| 3 | An image request pins the **default provider's vision model** (`get_vision_defaults`), no low-confidence escalation | One pinned model per image call; keeps vision on the same provider as the text default without a per-request model choice |
| 4 | ~~Vision rode the extraction A/B~~ → **the A/B is removed (ADR-025)**: there are no arms; text uses the env default, an image uses the provider's vision model | The experiment stack (assignment, arms, funnel analytics) was deleted when the model roster changed; extraction behaviour matches the always-disabled-experiment path |
| 5 | Prompt `v3v` = v3 + composed vision addendum | One source of truth, honest version label in logs/eval rows. Date table stays — leaflets print dates without years |
| 6 | `detail: "high"`, pinned | Leaflet value *is* the small print; `low` is one 512px thumbnail. ~765–1100 image tokens ≈ $0.002/call |
| 7 | Caption exempt from the 10-char floor | "for Mia" + image is a legitimate request; text-only keeps the floor |
| 8 | Synthetic golden images, generated by committed script | `scripts/generate_golden_images.py` — reproducible, zero real children's data; `transcript` key in expected JSON feeds the text-only LLM judge |

## Current eval state (run 2026-06-11, recorded in results.jsonl)

Three image cases in `tests/golden/`, swept with
`python -m evals.extraction.run --models openai/gpt-4o --cases img_07_leaflet,img_08_whatsapp,img_09_photo_no_year`:

| Case | Tests | Rule checks | Judge |
|------|-------|------------|-------|
| `img_07_leaflet` | Clean flyer; full date+year; time range; £ amount | 7/7 | 8/10 |
| `img_08_whatsapp` | Chat screenshot; "this Friday 3pm" → date table through vision | pass | 7/10 |
| `img_09_photo_no_year` | Angled, blurred, noisy photo; "Friday 19th June" no year → year inference | pass | 8/10 |

~2,950 prompt+completion tokens, **~$0.008 and 2.2–3.9 s per extraction**
(rows carry `input_type` and `image_bytes`; image tokens land in
`prompt_tokens`, so existing cost math holds). Non-vision combos print `[skip]`
for image cases (`VISION_CAPABLE` in `evals/extraction/run.py`).

**Model-comparison sweep (run 2026-06-12, `gpt-4o` vs `gpt-4o-mini`)**:
gpt-4o passed all rules (judge 7–9/10); gpt-4o-mini matched it on the
WhatsApp and no-year cases but dropped an action-item keyword on the leaflet
(6/7 rules) and scored one point lower on the noisy photo. Cost surprise:
mini's image-token multiplier (~27.7k prompt tokens vs gpt-4o's ~3k) erodes
its price edge — $0.0042 vs $0.0083 per extraction, ~½ rather than the ~16×
text-path saving. Results are filterable under the **Vision** tab on the admin
app's eval dashboard.

**Groq Scout vision (run 2026-06-12)**: the blocker behind decision #3 is
cleared — Groq's JSON mode **does** accept OpenAI-style `image_url` content
parts. Scout passed **all 19 rule checks** across the 3 image cases (including
year inference and the leaflet's time range + action items), judge 7/10 on
each, at **~1.0–1.7 s and ~$0.0005/extraction** — 2–3× faster and ~15× cheaper
than gpt-4o. Judge deductions are all description richness (fragmentary, omits
secondary details), not field correctness. Prod could now plausibly run one
provider for both paths; needs a wider/realer image set before switching
`vision_model`.

Two findings from the first sweep, both already addressed:

1. **gpt-4o dropped the printed end time** from "11:00am – 2:00pm" → added an
   explicit time-range rule to the v3v addendum (generic: ranges are ubiquitous
   on flyers).
2. **"Summer fair" classified `other`** — correct per v3's own taxonomy
   (fairs/festivals → other); the synthetic flyer, not the prompt, was wrong.
   Regenerated it with an explicit "Raising money for the PTA" line.

## Next: the vision eval (planned)

The current 3 synthetic cases prove the plumbing, not the quality envelope.
Synthetic renders photographed off a clean canvas are an *easier* test than
reality. The follow-up eval should:

- **Replace/augment with real photos** — crumpled backpack flyers, bad light,
  keystone distortion, glare. Same expected-JSON format; the golden contract
  doesn't change.
- **Widen the case set** — multi-event newsletters (pick the most prominent),
  handwritten notes, posters with stylised display fonts, a non-event image
  (failure case: confidence should drop, not hallucinate).
- **Model comparison on the image set** — `gpt-4o` vs `gpt-4o-mini` (already
  `VISION_CAPABLE`) vs **Groq Llama-4 Scout**, which is natively multimodal:
  if Scout-vision passes, prod could run one provider for both paths at ~⅓ the
  cost. Requires testing content-part messages under Groq JSON mode first —
  the reason Scout isn't in the vision path today. Candidate pricing surveyed
  in [`evals/extraction/model_selection.md`](evals/extraction/model_selection.md)
  (2026-06-12): Scout and Gemini Flash-Lite land ~$0.0004/extraction vs
  gpt-4o's measured $0.008, and Groq's vision docs now state JSON mode works
  with image input.
- **Per-field readout** — which fields degrade first as image quality drops
  (hypothesis: action-item small print before title/date).
